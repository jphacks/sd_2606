# 制度データ（手続き YAML）の書き方

`backend/data/procedures/` に **1手続き1ファイル** で置く。ファイル名は `id` と同じにする（例: `kokuho_enroll.yaml`）。
ファイルが分かれているので、複数人で同時に追加してもコンフリクトしにくい。どの制度を扱うか・作る順番は [procedure-list.md](procedure-list.md)。

```yaml
id: kokumin_nenkin                # ファイル名と同じ。英小文字と _
title: 国民年金（第1号被保険者）の手続き
category: pension                 # tax | insurance | pension | benefit | registration
summary: 1〜2文の説明
deadline: 会社を辞めたときは14日以内  # 任意。画面に出す期限の説明
due: {days: 14}                   # 任意。期限順の並べ替えに使う（下の「期限」）
office: 市区町村の役所              # 任意
relations:                        # きっかけの回答ごとの関係（下の「関係の書き方」）
  - field: annual_income
    op: gte
    value: 1500000
    flag: conditional
    score: 0.8
    reason: "年収 {annual_income}（150万円以上）、年末の年齢 {age_at_year_end}（19〜22歳）"
    when:                         # conditional（条件次第）の条件。すべて満たせば必須
      - {field: age_at_year_end, op: in, value: [19, 20, 21, 22]}
  - {field: part_time, value: "yes", flag: conditional, score: 0.4, reason: "アルバイト {part_time}"}
  - {field: part_time, value: "no", flag: unrelated, score: -1.0, reason: "アルバイト {part_time}"}
steps:                            # 手続きのフロー（アプリでタイムライン表示）
  - title: 書類をそろえる
    detail: 説明
    where: 市区町村の役所          # 任意
    documents: [離職票]            # 任意。アプリは全ステップ分を「必要なもの」にまとめる
    details:                      # 任意。詳しい手順の箇条書き（アプリでは「詳しい手順」を押すと開く）
      - 窓口では「国民年金被保険者関係届書（申出書）」に書きます
    when:                         # 任意。この説明が当てはまる人（下の「説明を人に合わせる」）
      - {field: supported_by, value: parent}
  - choice:                       # 任意。フローの分岐（下の「フローの分岐」）。title / detail は書かない
      field: nenkin_plan
      title: 保険料をどうするか選ぶ
      options:
        - {value: tokurei, label: 学生納付特例を使う, detail: 在学中は納めずに済みます。, steps: [...], amounts: [...]}
        - {value: pay, label: 保険料を納める, detail: 毎月納めます。, steps: [...], amounts: [...]}
reminders:                        # 任意。毎年・毎月の期限（アプリの「通知と履歴」に時系列で並べる）
  - {label: 確定申告の期限, month: 3, day: 15}          # 毎年 3/15。before_days（何日前から「もうすぐ」と出すか）を省くと7日前
  - {label: 国民年金保険料の納付期限（毎月末）, day: 31}  # month を省くと毎月。その月に無い日は月末
links:
  - {label: 日本年金機構, url: "https://..."}
```

## 関係の書き方（`relations`）

1行ごとに「きっかけ（`field` / `op` / `value`。例: アルバイトをしている、12月31日時点で20歳）」と、そのときの **状態・点数・理由** を書く。`op` を省くと `eq`。きっかけには、最初に聞く **年齢（生年月日から計算）・アルバイト・年収・扶養** を使う。アプリの対象は学生なので、学生に関係しない手続き（会社員・自営業向けなど）は書かない（以前のものは `backend/data/archive/`）。

| `flag` | 意味 | `score` | `reason` | `when` |
| --- | --- | --- | --- | --- |
| `required`（必須） | このきっかけなら必ず必要 | 正（0〜1） | 必要 | 書かない |
| `conditional`（条件次第） | `when` の条件をすべて満たせば必須。満たさない条件があれば、この行は数えない。`when` が無ければ点数だけ | `when` があれば正。無ければ -1〜1（負は関係を薄める） | 正の点数なら必要 | 任意 |
| `unrelated`（対象外） | このきっかけなら手続きは対象外（必須の行があれば必須が優先）。`when` があれば、すべて満たしたときだけ | 0 以下（-1〜0） | 任意（対象外の理由として出す） | 任意 |

アプリは手続きごとに次のように分ける（`backend/app/rules/engine.py` と `android/.../data/RuleEngine.kt` が同じ意味で判定する）。

1. きっかけに当てはまる行だけを数える
2. `required` の行か、条件をすべて満たした `conditional` の行があれば **「必要な手続き」**
3. そうでなく、`unrelated` の行が当てはまれば（`when` があればすべて満たせば） **「対象外の手続き」**（閉じたグループ。押すと開く）。例: 19〜22歳で年収136万円以下なら「親の扶養から外れる」は対象外
4. それ以外は **「関係がありそうな手続き」**。しきい値（`engine.py` の `THRESHOLD`）はいま -inf で、対象外でなければすべて出す。数値にすると、点数の合計がそれ未満のものは対象外のグループに回る
5. 並びは、関連度順（点数の合計が高い順）か期限順（`due` の近い順）をユーザーが選ぶ。理由は数えた行の `reason` を点数の高い順に出す

点数の目安:

- **1.0**: そのきっかけの代表的な手続き（今年20歳 → 国民年金）
- **0.5〜0.8**: 関係が強い（無職 → 国保・任意継続）
- **0.2〜0.3**: 年齢などから見た傾向（20代前半 → 親の扶養、20代 → 引越し）。ほかの行と足し合わせて並び順を決める
- **負（-0.3〜-0.8）**: 対象外ではないが関係が薄い（30歳以上 → 就職1〜2年目の住民税）。`when` の無い `conditional` に書く
- **対象外**: 法律上その人には関係しない（アルバイトをしていなければ年末調整は不要）は `unrelated` に、理由を添えて書く

### 未回答の項目と「判定には〇〇が必要です」

最初の画面で必ず答えてもらうのは、基本情報の **アルバイト（している／していない）・生年月日・扶養の状況・年収**（`questions.yaml` の `required: true`）。ほかの項目（健康保険）は任意で、最初の画面の「もっと詳しく（任意）」か、必要になった手続きのカードで聞く。

- 答えると判定（必要・対象外）が変わりうる項目があると、カードに **「判定には（項目名）が必要です」** と案内し、その場で入力できる。入れた値は端末に保存し、ほかの手続きの判定にも使う
- 一部の人にしか関係しない「はい / いいえ」の事情（掛け持ちなど）は `inline: true` にする。最初の画面では聞かず、判定に必要になった手続きのカードに **質問文と「はい / いいえ」をそのまま出す**。手続き YAML では `conditional` の `when` に書くと、「はい」で必要な手続きに移る（例: `kakutei_shinkoku.yaml` の `multiple_jobs`）
- `when` に未回答の条件が複数あるときは、**書いた順に1つずつ**聞く（「掛け持ちしていますか？」→「はい」なら「掛け持ち先の給与は20万円を超えますか？」）。前の条件が当てはまらないと分かれば、後ろは聞かない。年収のような答えてある条件を先に書くと、年収で決まる人には質問を出さない
- 年収は「見込み / 確定」を必ず選んでもらう（`income_basis`）。**見込み**なら、アプリは見込みの ±50% の幅で判定する。幅が条件の境目をまたぐ手続きは「関係がありそう」に入れ、カードに「「（手続き名）」が必要な場合があります」と出す（年収は聞き直さない）。**確定**なら円で入れてもらい、その額で判定する。サーバーの `recommend` は額そのもので判定する
  - `conditional` の `when` に未回答の項目がある（その行は点数だけ数える）
  - `required` の行や、`when` のある `conditional` の行のきっかけが未回答（例: 扶養している家族の人数 → 扶養控除）
  - `unrelated` の行のきっかけが未回答（例: 加入している健康保険 → 国保への加入）
- きっかけが未回答の行は数えない
- `age` / `age_at_year_end` を使うと、アプリは生年月日を聞く（保存するのは生年月日だけで、年齢は判定のたびに計算する）

## 期限（`due`）

期限順に並べるための値。`deadline` は画面に出す説明で、`due` は並べ替えだけに使う。期限の決まっていない手続きは書かない（最後に並ぶ）。

| 書き方 | 意味 | 例 |
| --- | --- | --- |
| `due: {days: 14}` | きっかけから何日以内（並べ替えでは今日をきっかけの日とみなす） | 国保への加入（14日以内） |
| `due: {month: 3, day: 15}` | 毎年の期限（今日以降で最初に来るその日） | 確定申告 |
| `due: {month: 6}` | 毎年その月の末日 | 住民税の納付 |

## 文章の書き方（読む量を減らす）

- `title` は **やること**（「〜を出す」「〜を届け出る」「〜を親に伝える」）。状況の説明（「〜の見込み」「〜になります」）はステップにしない
- `detail` は1文（いつ・どこで・どうやって）。なぜ必要か・払わないとどうなるかは書かない
- 書類の書き方・オンラインでの出し方など、詳しい手順が要るものは `details` に箇条書きで書く（最初は閉じて表示する）。1項目は1文で、`項目: 説明` のようにコロンと空白を続けて書かない（YAML の対応表として読まれる）
- `summary` は1文で「何の手続きか」。`reason` は「項目 本人の値（基準）」の形で、当てはまった条件を本人の回答と並べて書く（`"年収 {annual_income}（150万円以上）、年末の年齢 {age_at_year_end}（19〜22歳）"` → 「年収 160万円（150万円以上）、年末の年齢 20歳（19〜22歳）」）。差し込めるのは回答の項目と `age`・`age_at_year_end`。未回答だと「（年収は未入力）」になるので、必須の基本情報（アルバイト・生年月日・扶養・年収）か、その行のきっかけの項目だけを差し込む。なぜ必要かの説明は書かない。アプリは一覧のカードと手続きの画面に「当てはまる条件」「対象外の理由」の箇条書きとして出す（backend の `fill_in` も同じ表記）。`{` や半角のカンマ・コロンを含むので、`reason` はいつも `"` で囲む（1行の `{...}` の中ではカンマが区切りとして読まれ、文が切れる）
- 年齢・働き方・年収で分かれる内容は、条件の違うステップに分けて書き、文章に「（19〜22歳）」「20〜59歳は」のような但し書きを入れない（アプリは当てはまるステップだけを出すので、本人には不要）
- 「住民税がかかる見込み」のように、将来の日付に起きることは、いまは書かない（期限の日付に通知する仕組みを作るときに扱う）

## フローの分岐（`choice`）

本人が選ぶことで先の手順が変わる手続きは、ステップに `choice` を書いて2択（以上）に分ける（例: 国民年金 → 「学生納付特例を使う」「保険料を納める」）。

- 選択肢には `label`（名前）と `detail`（簡潔な説明1文）を書く。アプリは2つを並べ、選ぶとその選択肢の `steps` を続けて出す（番号も続く）。選び直せる
- 選んだ値は回答として端末に保存する（`field` に入る）。`reminders` と `amounts` の `when` に使える（例: 学生納付特例の申請の期限は `nenkin_plan` が `tokurei` のときだけ出す）。選ぶまでは、分岐の値を条件にした期限は出さない
- 選ぶまでは、分岐より先のステップとお金の目安を出さない

## お金の目安（`amounts`）

手続きの画面のフローの最後に「お金の目安」の欄を出す（分岐のある手続きは、選び終えてから）。金額はアプリが回答から端末内で計算する（`android/.../data/Amounts.kt`。回答は送らない）。YAML には何を出すかだけを書く。

- 手続きの `amounts` は、一覧のカードに出す **代表的な金額**（`card: true`。当てはまるもののうち最初の1つ）と、分岐の無い手続きの画面に出す金額
- 分岐のある手続きの画面には、選んだ選択肢の `amounts` を出す
- 欄は1行ずつ「名前　金額」と短い補足だけにし、計算の内訳は「計算の内訳」を押すと開く

```yaml
amounts:
  - kind: parent_deduction   # 種類（下の表）
    card: true               # 一覧のカードにも1行で出す（当てはまるもののうち最初の1つ）
    when:                    # 出す人の条件（ステップの when と同じ意味。すべて満たすときだけ）
      - {field: supported_by, value: parent}
```

| `kind` | 出すもの | 基準（2026年分・令和9年度分） |
| --- | --- | --- |
| `juminzei` | 本人の住民税（年額） | 給与所得控除 最低74万円、基礎控除43万円、税率10%、調整控除、均等割（森林環境税を含め5,000円）。給与所得45万円以下（年収119万円以下）は非課税。学生は勤労学生控除26万円 |
| `shotokuzei` | 本人の所得税（年額） | 給与所得控除 最低74万円、基礎控除104万円、税率5.105%。合計所得132万円（年収206万円）を超える人は出さない。学生は勤労学生控除27万円 |
| `parent_deduction` | 親が受ける控除（所得税） | 19〜22歳: 特定扶養控除63万円、136万円超は特定親族特別控除の表。16〜18歳・23〜69歳: 扶養控除38万円（136万円まで） |
| `nenkin` | 国民年金保険料 | 月17,920円（2026年度） |
| `nenkin_tokurei` | 学生納付特例を使うときの保険料 | 在学中は0円（後から納めるなら月17,920円） |

- 年収が未回答なら出さない。社会保険料控除など、聞いていない控除は含めない（画面に「目安です」と書く）
- 基準の出典は `Amounts.kt` の冒頭。税制が変わったら定数と `AmountsTest.kt` を直す

## 説明を人に合わせる（ステップの `when`）

ステップに `when` を書くと、その条件を満たさない人には表示しない（満たさない条件が1つでもあれば非表示）。未回答で分からない条件だけなら「当てはまる場合のみ」と添えて表示する。年齢や働き方で説明が変わるときは、条件の違うステップを並べて書く。

```yaml
steps:
  - title: 収入が150万円未満か確かめる
    detail: これから1年間の収入で判断します。
    when:
      - {field: age_at_year_end, op: in, value: [19, 20, 21, 22]}
  - title: 収入が130万円未満か確かめる
    detail: これから1年間の収入で判断します。
    when:
      - {field: age_at_year_end, op: not_in, value: [19, 20, 21, 22]}
```

「必要なもの」の一覧は、表示するステップの `documents` をまとめて作る（同じものは1つ）。当てはまるか分からないステップだけで使うものには「（当てはまる場合）」と添える。

`title` / `detail` に `{annual_income}` のように項目名を書くと、アプリがその人の回答に置き換える（「年収（{annual_income}）を親に伝える」→「年収（140万円）を親に伝える」）。使えるのは `questions.yaml` の項目と、生年月日から計算する `age`・`age_at_year_end`（「20歳」）。未回答なら「（年収は未入力）」になる。置き換えは端末の中で行い、回答は送らない。

## 条件に使えるもの

`field` は `UserProfile` の項目（[backend/app/schemas.py](../backend/app/schemas.py)）:

| field | 型 | 値 |
| --- | --- | --- |
| `part_time` | 文字列 | アルバイトをしているか: `"yes"` `"no"`（YAML では引用符で囲む。囲まないと真偽値になる） |
| `age` | 整数 | 今日時点の年齢（アプリは生年月日から計算する） |
| `age_at_year_end` | 整数 | その年の12月31日時点の年齢（生年月日から計算。所得税の控除や、19〜22歳の扶養の基準など、年末の年齢で決まる判定に使う） |
| `supported_by` | 文字列 | 親の扶養に入っているか: `parent` `none` `unknown` |
| `health_insurance` | 文字列 | いま入っている健康保険: `employer` `national` `dependent` `unknown` |
| `annual_income` | 整数 | アルバイトの年収（円。アプリでは万円で入力） |
| 分岐の `field` | 文字列 | その手続きのフローの分岐で選んだ値（例: `nenkin_plan`）。`reminders` と `amounts` の `when` に使う |

アプリの対象は学生なので、働き方（`occupation`）は聞かない（`UserProfile` には残してあり、省くと `student`）。

`op`: `eq` `ne` `in` `not_in` `contains`（リストに含む） `gte` `gt` `lte` `lt`

複数選択（multi）の項目では、`eq` / `in` は「選んだどれかが当てはまる」、`ne` / `not_in` は「選んだどれも当てはまらない」の意味になる。

## 質問の定義（`backend/data/questions.yaml`）

条件に使う項目は、すべてここに聞き方を書く（無いとテストが失敗する）。

```yaml
- field: part_time           # UserProfile の項目名
  kind: single               # single / multi / number（数値を入力）/ date（日付）/ range（数値の範囲を選ぶ）
  required: true             # 最初の画面で必ず答えてもらう基本情報か。多くの手続きの判定が変わる項目だけ true にする。
                             # single で必須にするなら「わからない」（unknown）の選択肢を入れる（アルバイトの有無は除く。テストで確認）
  text: アルバイトをしていますか？
  label: アルバイト           # 短い名前。「判定にはアルバイトが必要です」の案内に使う
  choices:                   # single / multi は選択肢を書く（value は schemas.py の Literal の値）
    - {value: "yes", label: している}
  # none_if_empty: true      # multi で何も選ばなかったとき「どれも当てはまらない」とする。
                             # 書かなければ未回答として、判定に必要なときにもう一度聞く
  # inline: true             # 最初の画面では聞かず、判定に必要になった手続きのカードの中でだけ質問文をそのまま出す。
                             # required と両方にはできない。yes / no の値は YAML の真偽値にならないよう引用符で囲む
  # part_of: annual_income   # その項目の欄の中で一緒に聞く（年収の「見込み / 確定」の income_basis）。単独の質問にはしない。
                             # 手続きの一覧の上部の年収の欄でも変えられる。判定には使わず、表示と AI への説明に使う

- field: birth_date
  kind: date
  required: true
  text: 生年月日は？
  label: 生年月日
  provides: [age, age_at_year_end]   # この日付からアプリが計算する項目（計算方法は RuleEngine.kt）

- field: annual_income
  kind: number
  text: 年収（税込み）は？
  label: 年収
  unit: 万円                 # 入力欄の単位
  scale: 10000               # 入力の単位（万円で入れて、円で保存・判定する）
```

`kind: range` にすると、選択肢を書かずに、手続き YAML の条件の境目から自動で作る（判定に必要な細かさでしか聞かない）。いまは使っていない。

## 内容の正確さ

制度の内容は公的機関のページ（国税庁・日本年金機構・厚生労働省・協会けんぽ・自治体）で確認し、`links` に出典を入れる。年収の基準は2025〜2026年に何度も変わっているので、令和8年分（2026年の収入）の値を使う（国税庁「源泉所得税の改正のあらまし（令和8年4月）」）。断定できない条件は `detail` に「詳しくは窓口で確認」と書く。
